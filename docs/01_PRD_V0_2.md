# TitleLab 微信小程序化重建 PRD v0.2

当前阶段：Phase 0 - 文档治理与架构确认

## 1. 产品目标

将 TitleLab 从现有静态网页/PWA 工具重建为“小程序 + 后端 API + 管理后台 + 数据库”的长期可维护系统。v0.2 重点是明确需求边界、数据模型和分阶段路线，不进入实现。

成功标准：

- 能解释现有 Web 功能如何迁移到小程序和后台。
- 能明确用户体系、标题/文案/内容模型、分类标签、收藏、历史、生成记录和审核配置。
- 能为 Phase 1 的后端骨架、数据库基础 migration、`healthz` / `meta` 提供清晰输入。

## 2. 核心场景

- 运营查找素材：按关键词、主分类、账号分类、场景标签查找标题或文案。
- 运营快速复用：复制标题/文案，收藏/星标高价值素材，查看最近使用记录。
- 整理素材：批量导入多行标题/文案，预览识别结果，归入分类和账号分类。
- 管理素材：管理员新增、编辑、删除、去重、导出、审核、恢复快照。
- AI 辅助：基于参考标题生成候选标题，保存生成结果和使用记录。
- 多用户隔离：不同用户只能访问授权 workspace 下的数据，管理员可跨用户/空间管理。

## 3. 用户与权限

### 3.1 用户类型

- 普通用户：浏览、搜索、复制、收藏、查看个人历史和生成记录。
- 编辑用户：可新增、编辑、批量导入授权 workspace 内的标题/文案。
- 管理员：可管理用户、分类、模板、审核状态、系统配置、导出和危险操作。

### 3.2 权限原则

- 登录认证必须由后端完成，禁止继续使用前端硬编码账号作为正式认证。
- 所有业务数据必须归属 workspace。
- 用户访问数据必须校验 workspace membership 和角色。
- 管理端危险操作必须有二次确认和审计记录。

## 4. 功能规划

### 4.1 小程序端

- 登录与会话：微信登录/后端会话、用户资料、当前 workspace。
- 首页：标题/文案入口、最近使用、星标内容、常用分类。
- 标题库：列表、搜索、筛选、详情、复制、收藏/星标、使用记录。
- 文案库：列表、搜索、筛选、详情、复制、收藏/星标、使用记录。
- 分类筛选：主分类、账号分类、场景标签、模板类型。
- 历史记录：复制历史、查看历史、AI 生成历史。
- 设置：个人显示偏好、默认 workspace、缓存清理提示。

Phase 3 只读 MVP 只做浏览、搜索、详情、复制和收藏，不做复杂编辑。

### 4.2 后台管理端

- 用户与 workspace 管理：用户、角色、成员关系。
- 内容管理：标题、文案、模板的新增/编辑/删除/审核/上下架。
- 分类标签管理：主分类、账号分类、场景标签、排序、禁用。
- 批量导入：多行文本导入、识别预览、去重提示、导入批次记录。
- 快照与导出：数据快照、CSV/JSON 导出、恢复前预览。
- AI 配置：模型/代理配置由后端保存，前端不暴露密钥。
- 审计日志：登录、导入、删除、导出、审核、危险操作。

### 4.3 API 模块

- Auth API：微信登录、会话刷新、退出、当前用户。
- Workspace API：workspace、成员、角色。
- Content API：标题/文案 CRUD、搜索、筛选、状态流转。
- Taxonomy API：分类、标签、账号分类、排序。
- Favorite API：收藏/星标、取消收藏、星标列表。
- History API：复制历史、查看历史、导入历史、生成历史。
- Import API：批量导入预览、确认导入、导入批次。
- Snapshot API：保存快照、列表、加载、删除、导出。
- Admin API：用户管理、审核、系统配置、审计日志。
- AI API：标题仿写请求、生成结果保存、成本/耗时记录。
- Health API：`/healthz`、`/meta`、版本与环境只读信息。

## 5. 内容与数据需求

### 5.1 标题/文案/内容数据模型

- 标题与文案应共享基础内容模型，通过 `content_type` 区分 `title`、`copy`、`template`。
- 标题字段包括正文、主分类、账号分类、场景标签、星标、审核状态、来源、排序权重。
- 文案字段包括正文、主分类、账号分类、场景标签、星标、审核状态、来源、排序权重。
- 模板字段用于后续 AI 生成和内容结构化复用，可在 Phase 4 后扩展。

### 5.2 分类/标签/模板体系

- 主分类：内容业务分类，可排序，可禁用。
- 账号分类：当前网页中的“账号分类”，用于不同账号/内容场景筛选。
- 场景标签：多选标签，如地点、活动、主题、拍摄场景。
- 模板：面向 AI 仿写或固定内容结构，后续可关联提示词、示例、适用场景。

### 5.3 收藏/历史/生成记录

- 收藏/星标：用户维度，不直接改动原始内容质量状态。
- 历史记录：记录浏览、复制、导入、生成等事件，用于最近使用和审计。
- 生成记录：保存输入参考、模型、输出、耗时、成本、采用状态，避免只存在客户端。

## 6. 非功能需求

- 移动优先：小程序端优先支持单手浏览、搜索、复制。
- 数据隔离：所有数据必须有 workspace 和用户权限边界。
- 可审计：删除、导出、导入、审核、AI 生成必须留痕。
- 安全：密钥只在服务端或私有配置中保存；小程序和静态前端不得出现 AppSecret、API Key、数据库连接串。
- 合规：遵守微信小程序内容安全、合法域名、备案主体和用户隐私告知要求。
- 可迁移：数据库设计要允许从当前 Supabase 快照/localStorage 数据迁移。

## 7. 明确不做

- 本轮不开发后端、小程序、管理后台代码。
- 本轮不创建数据库 migration。
- 本轮不迁移真实数据。
- 本轮不部署服务器、不配置域名、不提交微信审核。
- 本轮不 push、不 commit。
